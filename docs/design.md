# BLLA trading system 设计决策

## 目标与范围

`blla_trading_system` 以书中 Chapter12 为主实现，保留书中最终交易生态，并接入 SimNow 进行中国期货模拟交易。第一阶段同时支持：

- 本地模式：书中的 `exchange_main` 与一个或多个 `trading_main`。
- SimNow 模式：独立的 `simnow_gateway` 与 `trading_main`。

系统重点是交易基础设施。策略只保留书中的 MAKER、TAKER 和必要的 RANDOM 示例，不新增复杂信号或策略框架。

## 架构决策

每个进程内部采用书中的线程和无锁队列模型。交易所进程包含订单服务器、撮合引擎、行情发布和快照线程。交易客户端进程包含订单网关、行情消费者和交易引擎线程；交易引擎内部同步调用订单簿、持仓、特征、策略、订单管理和风控组件。

`simnow_gateway` 是独立进程，负责 CTP/SimNow 登录、查询、行情订阅、报单、撤单、成交回报、错误处理和连接状态。它通过扩展后的 TCP 订单协议和 UDP 行情协议与 `trading_main` 通信。协议明确区分盘口/订单簿更新、逐笔成交事件和自身订单回报，不把不同语义的消息混用。

以 Chapter12 为系统基线只保留一份 `common`、`exchange`、`trading` 主实现。早期章节的独立示例放入 `examples`，性能对比代码放入 `benchmarks`，并记录章节代码的归属。Chapter12 的优化实现先作为对比基准，不自动替换主路径。

## 期货交易语义

订单管理层把策略的买卖意图转换为开平指令：有反向持仓时先平仓，没有反向持仓再开仓。平仓必须成交并更新持仓后，才允许后续开仓判断。若意图数量超过反向持仓，只提交可平数量，不保留剩余开仓意图，等待策略重新决策。

模型必须支持合约最小价格变动、合约乘数、开仓/平仓、平今/平昨、可平数量、挂单冻结、订单状态和成交回报。数量统一按手处理，盈亏计算纳入合约乘数。

启动策略前查询账户和目标合约，要求目标合约空仓且无活动挂单。第一阶段限定一个账户、一个目标合约和一个交易客户端，MAKER 与 TAKER 分别验证。

## 风控、停止与故障

保留书中的最大单笔数量、最大持仓和最大亏损检查，并增加 tick、乘数、可平数量及挂单冻结检查。触发最大亏损后暂停策略、停止新报单、撤销本次运行的活动订单、保留持仓并输出告警，不自动平仓。

正常停止时停止新订单，撤销本次运行的活动订单，等待撤单结果，输出未确认订单和剩余持仓后退出。行情、交易或进程间连接中断时暂停策略，不自动恢复；连接重新建立后也不自动重启策略。

## 构建、配置与运行

统一使用 Linux/WSL2 Ubuntu、C++20、GCC 和 CMake。账户、合约、地址、端口、组播、限额及策略参数使用 TOML；SimNow 凭据通过本地 `.env` 提供，真实 `.env` 必须加入 Git 忽略，仓库只保存 `.env.example`。

提供独立运行脚本：`run_local_exchange.sh`、`run_local_clients.sh`、`run_simnow_gateway.sh` 和 `run_simnow_client.sh`。脚本明确启动顺序、配置文件、日志目录和停止方式。

## 第一阶段验收

1. 项目可构建。
2. 本地 `exchange_main` 与 `trading_main` 示例可运行。
3. SimNow 模式可完成登录、查询、行情接收、MAKER/TAKER 自动运行、报单、撤单及成交或拒单回报。
4. 正常停止能撤单并输出状态。
5. 凭据不进入 Git，配置和日志路径可复现。
